# المكتبة الإسلامية — «نور الهدى» + «بوابة النور»

مشروع ويب عربي إسلامي (RTL) بلا خطوة بناء للواجهة: HTML + CSS + وحدات ES.

هذا المشروع من إعداد المؤلف marwan13579: المحتوى، والتصميم، والبناء، والنشر.

يحتوي على:

| الصفحة | الوصف |
|--------|-------|
| `src/site/noor.html` | **موقع نور الهدى** — صفحة واحدة بستة عشر قسمًا مع scroll-spy واختبارات وشهادات |
| `src/app/app.html` | **تطبيق بوابة النور** — اثنا عشر تبويبًا (مصحف، أذكار، مواقيت، زكاة، إذاعة، بطاقات…) |
| `index.html` | **الرفيق اليومي + فهرس المكتبة** — لوحة اليوم (الصلاة القادمة، الورد، آية وذكر اليوم) فوق فهرس الأدوات القائم كما هو |
| `catalog.pdf` | **الكتالوج التعريفي** — ٢٢ صفحة PDF مولّدة من الموقع نفسه، ورابطه في تذييل الفهرس |

## الكتالوج التعريفي

`catalog.pdf` دليل مطبوع تعريفي بالموقع: كل ما فيه مولَّد من مصادر الموقع نفسها
لا مكتوب بخط اليد، فهو لا يقدّم على مصدره ولا يفترق عنه:

- أسماء الأدوات ووصفها وأقسامها من `const TOOLS` و`const CATS` في `index.html`.
- الأعداد الكبيرة (الاختبارات، الفتاوى، الخطب، التفسير، السِراج، حصن المسلم،
  القرّاء والإذاعات، ومداخل البحث) من `content/manifest.json` وهو فهرس المحتوى
  الذي تقرأ منه الصفحات.
- الأقسام والتبويبات والدروس والأدعية والأحاديث تُعدّ من ملفاتها في `src/data`
  و`src/site` و`src/app`.

```sh
npm run catalog         # يبني catalog.pdf
npm run catalog:check   # يفشل إن كان الملف لا يطابق ما في الموقع

# أو مباشرة، بعد إعداد البيئة مرة واحدة:
python3 -m venv .catalog-venv
.catalog-venv/bin/pip install -r scripts/requirements-catalog.txt
python3 scripts/make-catalog.py            # بناء
python3 scripts/make-catalog.py --check    # فحص الانحراف
```

> البناء يحتاج Python مع ReportLab وخطوط Noto العربية (على دبيان:
> `apt install fonts-noto-core`). فإن لم تتوفّر البيئة تتخطّى الخطوة برسالة
> ولا تُفشل فحوص الموقع، لأن الملف نصّ يُرفع مع الموقع لا شرط في بنائه.
> البناء ثابت البايتات: الملف نفسه يُنتَج من المصادر نفسها بايتًا ببايت.

## التجهيز والتشغيل

```sh
npm ci                 # ثبّت الاعتمادات (Tailwind + خطوط محلية)
npm run build          # CSS + نسخ الخطوط والأدوات إلى vendor/
npm run build:pages    # أنشئ dist/ جاهزًا لـ Vercel
npm run serve          # python3 -m http.server 8765
```

في Vercel استخدم أمر البناء `npm run build:pages` ومجلد الإخراج `dist`.
يحتوي الناتج ملفات التشغيل فقط، ويتحقق قبل النشر من وجود كل ملفات Service Worker.

### النشر

المشروع على Vercel تحت الاسم `islamic-library`، والنشر يتم تلقائيًا
عند كل push على `main` عبر `.github/workflows/deploy.yml`: مهمة `verify`
تشغّل `npm test` وفحصي الصيغة والأيقونات، ومهمة `deploy` تبني ثم ترفع `dist/`.

```sh
git push origin main    # يبني وينشر تلقيميًا
```

الإعداد في `vercel.json`: أمر البناء `npm run build:pages` ومجلد الإخراج `dist`
مع ترويسات الأمان (X-Content-Type-Options، X-Frame-Options، …).
نُشر على <https://islamic-library-green.vercel.app>.

للنشر من الجهاز:

```sh
vercel --prebuilt
```

استعمل `--prebuilt` دائمًا: البناء على خوادم Vercel يخطئ في `npm ci`،
لكن البناء المحلي يُنتج `dist/` صحيحًا وينشر دون خطوة بناء.

ثم افتح `http://localhost:8765/src/site/noor.html` أو `.../src/app/app.html`.
يلزم HTTP عبر localhost أو HTTPS لتفعيل Service Worker والإشعارات وتحديد الموقع.

### لا تفتح الملف بنقرة مزدوجة

الفتح المباشر من القرص (`file://`) يُظهر صفحات **فارغة**، وهذا متوقّع لا عطل في المشروع:

- المتصفح يمنع وحدات ES من `file://` لأن أصل الصفحة `null`، فترفض السكربتات بصمت.
- ويمنع `fetch` قراءة ملف محلي من القرص.
- وعامل الخدمة (Service Worker) لا يُسجَّل أصلًا إلا على http أو https.

لذلك تُحمَّل `src/lib/serve-hint.js` في الصفحات المتأثرة، فتكتشف بروتوكول `file:`
وتعرض سبب الفراغ مع الأمر المطلوب بدل الشاشة البيضاء.

الصفحات المتأثرة: `src/site/noor.html` و`src/app/app.html` (وحدات ES)،
و`30-quran-full.html` (قراءة `vendor/quran-arabic.json` بـ `fetch`).
أما `index.html` وبقية الأدوات فسكربتات عادية وتعمل من القرص،
(و`33-academy.html` صار صفحة تحويل إلى نور الهدى بعد دمجهما)
مع شريط تنبيه أعلى الصفحة.

## الرفيق اليومي

في أعلى `index.html` لوحة «اليوم» فوق فهرس الأدوات — ولم يُحذف من الفهرس
شيء ولا رابط.

Flow: الصلاة القادمة ← الورد ← آية/ذكر اليوم ← المشاركة.

| الملف | الدور |
|-------|-------|
| `daily-companion.js` | المحرّك: المواقيت، خطط الورد، الأيام المتتالية، المشاركة، التذكيرات (‏UMD كـ`khatma-core.js` فيُختبر وحده) |
| `daily-content.js` | **مولَّد آليًا** من `src/data/daily.js` + `app-daily.js` + `app-duas.js` — لا تُنسخ نصوصه يدويًا |
| `daily-home.js` | يبني اللوحة في `#dcRoot` ويجعل روابطها وتذكيراتها |
| `daily-companion.css` | تنسيق اللوحة على متغيّرات `index.html` نفسها (لا نظام ألوان جديد) |
| `scripts/build-daily-content.cjs` | يولّد `daily-content.js`، و`--check` يفشل إن تخلّف عن المصدر |
| `scripts/daily-hub-check.mjs` | فحص Chromium للوحة (٤٩ تحقّقًا، منها ١٣ للجولة التعريفية) |

**مبدأ المحتوى الديني:** لا نصّ ديني في هذه الملفات. كل آية أو حديث أو
دعاء يأتي من `daily-content.js` المولَّد من وحدات البيانات، **وكل عنصر
فيه مرجع** (يفحصه `tests/daily-companion.test.js`). فإن غاب المصدر فلا
يظهر نصّ — ولا يُخترع بديل.

شاشة إتمام الورد تعرض آية أو حديثًا أو فائدة أو دعاءً **فقط**؛ لا
«تفسيرًا مختصرًا» ولا «قصة»، لأن ذلك بابٌ لختراع ينسب إلى الدين.

**المفاتيح** كلها تحت بادئة `dc-` فلا تمسّ مفاتيح الأدوات القائمة
(`wird-goal` · `khatma_state` · `mushaf-progress` …):

| المفتاح | المحتوى |
|---------|---------|
| `dc-plan` · `dc-log` · `dc-streak` | الخطة · سجلّ الصفحات بالأيام · السلسلة |
| `dc-reminders` | التذكيرات (مطفأة افتراضيًا) |
| `dc-prefs` · `dc-saved` · `dc-tapped` | الموقع وطريقة الحساب · المحفوظات · عدّاد الذكر |

**التذكيرات:** إشعاراتُ الموقع تشتغل وحدها بلا زرّ: يُطلب الإذن تلقائيًّا
عند فتح الصفحة ثم عند أوّل لمسة (لأنّ المتصفّح لا يقبل الطلب قبلها)،
ويخرج إشعار ترحيب في كل فتح من أيّ صفحة — يعرضه عامل الخدمة، فيعمل
بعد إغفاء الصفحة — وجدولُ أذانٍ يُرنّ في وقته ما دام المتصفح حيًّا،
ويؤخَّر يومًا بعد يوم فلا يسقط بعد آخر صلاة. أمّا الإشعارات والمتصفّح
مغلقان تمامًا فتحتاج Web Push بخدمة خلفية، وهي غير مضافة — فلم يُوهم
المستخدم بذلك. وتذكيرات الرفيق (`prayer` · `wird` · `morning` · `evening`
· `daily`) لكلٍّ منها وقت يُضبط، وهي تعمل ما دامت الصفحة مفتوحة.

## رفيق النور

تذكير إيماني لطيف أثناء القراءة: بطاقة صغيرة أسفل الصفحة تحمل آية أو
ذكرًا أو دعاءً أو خبرًا وأثرًا، و**تدبّرًا** بعد إتمام السورة، مع اقتراح
عملٍ واحد صغير. لا حساب ولا تسجيل ولا تتبّع ولا طلب شبكة.

الاسم عمدًا: هو **رفيق** لا **مُنبِّه** — لا إزعاج ولا أرقام، والخصوصية
والمصادر مقدّمة على كل شيء.

| الملف | الدور |
|-------|-------|
| `noor-companion.js` | المحرّك كاملًا (IIFE/‏UMD بلا وحدات، فيعمل بوسم `<script>` وحده) |
| `noor-content.js` | **مولَّد آليًا** — ٢٧١ عنصرًا من `scripts/noor-curation.mjs`، لا تُنسخ نصوصه يدويًا |
| `44-noor-companion.html` | صفحة الإعدادات: الفاصل، الأنواع، الوضع الهادئ، الإشعارات، الأعمال، الرحلة، الخصوصية |
| `scripts/build-noor-content.mjs` | يولّد `noor-content.js`، و`--check` يفشل إن تخلّف عن المصدر |
| `scripts/noor-check.mjs` | ٥٩ فحصًا سلوكيًّا في Chromium (ترحيب، إذن، تدبّر، منع تكرار، بلا اتصال) |
| `tests/noor-companion.test.js` | ٢٤ فحصًا: المحتوى، التخزين، المحرّك، أنماط وقت التشغيل، الربط |

**مبدأ المحتوى** موروث من الرفيق اليومي ولا يُخالَف: كل نصّ منسوب إلى
مصدره، وما هو تأليفٌ تحريري (التدبّر والأخبار والآثار والأعمال) مُوسَم
`editorial` **بلا مصدر** — لأن نسبة تأليفٍ تحريري إلى النبي ﷺ أو إلى كتاب
اختراعٌ في الدين. وفحص `tests/noor-companion.test.js` يحرس ذلك.

وأسئلة الأدعية تُنسب بصيغة «رواه فلان» لا باسم الكتاب مجرّدًا، لئلّا يُقرأ
كلامُ الراوي دعاءً من عنده. والمراجع القرآنية (`البقرة: 201`) تُترك كما
هي، فالقرآن لا يُروى عن راوٍ. وتفققُ العناوين مع `25-azkar-shamila.html`
مفحوص: وصفٌ واحد في موضعين تناقضٌ يَحُسّه المستخدم.

**الخصوصية** هي المبدأ الحاكم: صفر طلبات إلى مواقع أخرى (يفحصه
`noor-check.mjs`)، ولا حساب، وحذفُ الإحصاءات لا يمسّ تقدّم القراءة. والنظام
يقرأ `quran-lastpos` ويكتفِ، فلا يكتب مفتاح تقدّم موازيًا.

**التركيب:** `<script src="noor-companion.js" defer></script>` في ٤٧
صفحة، مستثناةً `offline.html` (صفحة الخطأ). سطر واحد لا غير، فالإزالة
بحذفه. ويُستثنى `33-academy.html` ومجلدا الفيديو لأن لهما هيكلهما.

**الإزعاج** هو ما يُحذَر منه: لا مؤقّتات في الوضع الهادئ أو عند إطفاء
التذكير (مفحوص)، ولا تذكير أثناء الكتابة، ولا تكرار (سجلّ `noor-shown`
يقصّ الهامش)، ولا سؤال إذن إلا بعد موافقة، ولا يُعاد بعد الرفض.

**المفاتيح** تحت بادئة `noor-`، مُعلَنة في المواضع الثلاثة التي يفحصها
`tests/noor-companion.test.js`: `KEYS` و`IMPORT_TYPES` في
`src/lib/storage.js`، و`ALLOWED_KEYS` في `backup-core.js`.

| المفتاح | المحتوى |
|---------|---------|
| `noor-settings` | الفاصل (٥ دقائق افتراضيًّا) · الأنواع · الوضع الهادئ · حالة الترحيب |
| `noor-shown` | سجلّ ما عُرض، فلا يتكرّر |
| `noor-stats` | الرحلة: جلسات · أجزاء · سور · تدبّرات · أعمال |
| `noor-actions` | أعمال اليوم المختارة (تُصفَّر مع تغيّر اليوم) |

## دليل المكتبة

أول ما يفتحه زائرٌ جديد: جولةٌ تعريفية **شاملة** يعرف منها ما هذا الموقع،
وما فيه بالتفصيل، ومن أين يبدأ. تظهر مرّة واحدة (`hub-intro-seen`)،
ويفتحها زرّ «دليل المكتبة» في ترويسة الفهرس في أيّ وقت، وتتبع لغة الصفحة
فتتبدّل النصوص أمام المستخدم المفتوحة.

**اثنتا عشرة خطوة** تُبنى من الفهرس نفسه، فلا تُناقض ما يراه الزائر:

| الخطوة | ما فيها |
|--------|---------|
| الترحيب | نبذة الموقع + عدّاداته: كم أداة وكم قسمًا، وبأي لغتين، وبلا تسجيل ولا إنترنت ولا تتبّع |
| لوحة «اليوم» | كل بطاقة فيها بالتفصيل: الصلاة القادمة والعدّ، الورد وخططه، آية اليوم وذكره، «ماذا تفعل الآن»، الاختصارات، التذكيرات الاختيارية، الوضع الليلي، وشاشة الإتمام بمصدرها |
| كل ما في الفهرس | البحث، شريط الأقسام، المفضّلة، الملاحظات، الترتيب، اللغة، السمة، التثبيت، التصدير والاستيراد، الكتالوج، الدليل، والعمل بلا إنترنت والخصوصية |
| الأقسام | الأقسام الستة بأسمائها وعدد أدواتها ووصف كلٍّ منها |
| خطوة لكل قسم | **كل أداة** في القسم باسمها ووصفها ورابطها — ٦٨ أداة لا تسقط منها واحدة (يفحصها `scripts/daily-hub-check.mjs`) |
| مواضع أخرى | موقع نور الهدى وبوابة النور ومكتبة الفيديو، بأوصافها من بطاقاتها |
| من أين تبدأ | ثلاث أدواتٍ للبدء + دعوة إلى الإخلاص |

**لا تكرار في النصوص:** الأسماء والأعداد والأوصاف كلُّها تُقرأ من الفهرس
بعد تصييره (`data-cat` على شريط الأقسام، و`data-section`/`data-blurb`
على كل قسم، و`data-tool` على كل بطاقة)، فلا يمكن للجولة أن تخالف الفهرس
في عددٍ أو اسمٍ أو رابط. وروابط الخطوات كلها ملفاتٌ موجودة، ولا نصّ
دينيًّا في الجولة: تعريفٌ بالموقع وأدواته فقط.

| الملف | الدور |
|-------|-------|
| `intro-tour.js` | نصوصُ الجولة (عربي/إنجليزي) + قراءةُ الفهرس + بناءُ الخطوات + النافذة (‏UMD بلا وحدات) |
| `intro-tour.css` | تنسيق النافذة على متغيّرات `index.html` نفسها (لا نظام ألوان جديد) |
| `tests/intro-tour.test.js` | ٢٤ فحصًا: الروابط، العدّادات، اللغتان، النافذة على شجرة DOM مُصطنعة |
| `scripts/daily-hub-check.mjs` | ١٧ فحصًا للجولة في Chromium (ظهورٌ واحد، تغطية كل الأدوات، لغتان، ٣٦٠ بكسل) |

**المفاتيح** تحت بادئة `hub-intro-` (لا `hub-` وحدها، فلا تختلط بمفاتيح
الفهرس)، مُعلَنة في المواضع الثلاثة التي يفحصها
`tests/library-keys.test.js`:

| المفتاح | المحتوى |
|---------|---------|
| `hub-intro-seen` | نسخة الجولة التي رآها الزائر — فترفعها فتُعاد الجولة |
| `hub-intro-step` | الخطوة التي وقف عندها، فتفتح الجولة اليدوية من هناك |

**فحوص الفهرس** التي تنقر على الصفحة تُزرع فيها نسخةُ الجولة الحالية قبل
التحميل (`skipIntro` في `daily-hub-check.mjs`، و`openPage` في
`noor-check.mjs`، وكلاهما يقرأ `VERSION` من `intro-tour.js` فلا يتقادم
معها)؛ الجولة تحجب الصفحة أوّل فتح، وهذه الفحوص تفحص ما تحتها. وفحص
الجولة نفسه قسمٌ مستقلٌّ في `daily-hub-check.mjs` بلا الزرع.

**التغييرات:** عدّل النصوص في `STR` (المفتاحان `ar` و`en` متكافئان
مفتاحًا بمفتاح ويفحصه الاختبار)، وارفع `VERSION` إن أردتَ أن يرى
الزائر القديم الجولة الجديدة — وسيعرف الفحصُ النسخةَ الجديدة تلقائيًّا.

## SEO

`prepare-pages.cjs` يولّد في `dist/` ملفّي `sitemap.xml` و`robots.txt`،
باستخدام نطاق المشروع على Vercel. القيمة الافتراضية
`https://islamic-library-green.vercel.app`، وبدّلها بمتغيّر بيئة إذا
نشرت على نطاق مخصص:

```sh
SITE_ORIGIN=https://your-domain.com npm run build:pages
```

`robots.txt` يسمح للجميع (لا إعلانات ولا تتبّع) ويشير إلى ملف sitemap فقط.

روابط مختصرة جديدة في `vercel.json` مثل `/quran` و`/azkar/morning`
و`/prayer-times`. كلها تحويلات ٣٠١ إلى صفحات قائمة، ولا واحد منها يحجب
ملفًا موجودًا — ويفحص ذلك اختبار.

## السِراج في بيان غريب القرآن

صفحة `43-siraj.html` تفتح غريب القرآن الكريم سورةً سورة: لكل مدخل لفظُه
ومعناه، ومعه نصُّ الآية من المصحف مبرزًا فيه لفظُه ومواضعُه الأخرى في
المصحف، وبحثٌ في كلمات الكتاب كلّه.

محتواها نصُّ كتاب **«السراج في بيان غريب القرآن»** للدكتور محمد بن عبد
العزيز الخضيري، الطبعة الثانية (الرياض ١٤٢٩ هـ / ٢٠٠٨ م)، ونصّه الرقمي
من [المكتبة الشاملة](https://shamela.ws/book/14531). وهو ٦١١١ لغوًا في
١١٤ سورة، وفهرسُه ٦٩٤٨ كلمة موزّعة في ٢٨ دلوًا على أوائل الحروف، فالبحث
يقرأ دلوًا واحدًا لا الكتاب كلّه.

```sh
npm run download:siraj   # يجلب نصّ الكتاب رقميًا: sources/siraj/raw.json
npm run build:siraj      # يبني منه content/siraj/ (١١٤ ملف سورة + الدلاء)
```

ومن القرآن إليه بابان: «غريب السورة» في ترويسة سورة **المصحف الكامل**
(`30-quran-full.html`) وفي ترويسة سورة **التفسير الميسر**
(`35-tafsir.html`)، وكلاهما يفتح غرائب السورة بعينها في `43-siraj.html?s=N`.

والبحث موحّدٌ في مربّع البحث بالأعلى: يغطي كلَّ المحتوى من مكان واحد،
وكل نوع نتيجة يوصل إلى صفحته مباشرة.

هذا المحتوى **ليس** من Altaqwaa كسائر المحتوى المستورد، فبُني بسكربتيه:
`fetch-siraj-source.cjs` يجلب نصًّا مطبوعًا لا استخراجًا ضوئيًا، متسلسلًا
بمهلة بين الطلبات ومستأنفًا من حيث وقف، ثم `build-siraj-content.cjs`
يحوّله إلى ملفات. والبناء **يمتحن** الكتابَ على المصحف: يقارن عدد آيات
كل سورة بـ `content/surahs.json`، ويؤكّد أن رقم آية كل مدخل داخل مدى
السورة، ويرمي عند الخلل.

## ما كان مكتوبًا ولا يعمل — أُصلح

كل فحوص `check:all` كانت تنجح لأن الفحص الساكن
(`tests/wiring.test.js`) لا يرى إلا `data-role`، فقد مرّت أزرار صامتة كلّها.
كشف الفحص في المتصفح (ضغط كل زرّ ومقارنة DOM) العيوب التالية، وكلها أُصلحت
مع اختبار يمنع عودتها في `tests/wiring-deps.test.js`:

| العيب | السبب | الإصلاح |
|---|---|---|
| نسخ الدعاء لا يفعل شيئًا في الموقع | الزر كُتب بـ `data-copy-dua` فقط والمعالج يقرأ `data-role` | `src/site/render.js` صار يصدّر السمةين |
| شرائح تصنيف الأدعية والإذاعة والأحاديث صامتة | لا معالج نقر، وكل الشرائح تحمل `active` | `switchCat()` في `src/app/app.js` + `catChipsHtml()` في `tabs.js` |
| «مكية/مدنية» في قائمة السور صامت | `data-type` كان يحمل اسمًا عربيًّا والقائمة تطلب `Meccan` | المفتاح الإنجليزي في السمة والعربي في العرض |
| العلامات في المصحف لا تُحفظ ولا تُفتح | `quran_bookmarks` كانت تُقرأ ولا تُكتب، والشريحة بلا معالج | زرّ «🔖 حفظ العلامة» + `bookmarkKey`/`parseBookmark` |
| زرّ «راجع» في مراجعة الاختبار صامت | `data-review` بلا معالج | صفّ تفاصيل مخفيّ يُفتح ويُغلق مع `aria-expanded` |
| `1-adhkar.html` غير مفهرسة | بطاقة ناقصة في `TOOLS` | أُضيفت `dhikrkit` بالعربية والإنجليزية |

كذلك حُذف كل تصدير بلا مستهلك (`downloadCertificate` · `hideToast` · `debounce`
استُعمل في بحث الموقع · `seededPick` · `onInstalled` · `ensureNotificationPermission` ·
`refIsAuthoritative` · `EXTRA_LESSON_IDS`)، وصار `tests/wiring-deps.test.js`
يفشل إن تكرّر تصدير بلا مستهلك.

## دروس الآداب المضافة

خمسة دروس كانت مطلوبة ولم تكن في المشروع، أُضيفت في `src/data/lessons-extra.js`
لأن `lessons.js` مولَّد آليًا من المصدر ويُمحى فيه أي تعديل يدوي.

| الدرس | المعرّف | الآيات |
|---|---|---|
| آداب حسن الضيافة | `host` | المائدة ٢ · الصافات ٢٤ |
| آداب اللبس | `dress` | الأعراف ٣١ · الأعراف ٣٢ |
| غسل الميت وتكفينه | `janazah` | آل عمران ١٨٥ · المائدة ٣ |
| بر الأبناء | `offspring` | لقمان ١٤ · نوح ٢٨ |
| آداب زيارة المريض | `visit` | المائدة ٢ · البقرة ٢٦٣ |

وإضافةً إليها: درس **آداب الطعام** كان بلا آية، فصار له آيتان (المائدة ٨٨ · البقرة ١٧٣).

**اختيار المعرّفات لم يكن عشوائيًا**: `lessons.js` كان يشير إلى `host` و`visit`
روابطَ معلّقة في `related` لأن الدرسين لم يكونا موجودين، فسُمّيت المضافة بهذين
المعرّفَين فعادت الروابط إلى العمل. اختبار `المعرّفات القديمة المعلّقة صارت موجودة` يمنع
عودة أي رابط معلّق.

### التحقّق من الآيات — لا بالذاكرة

كل آية تُقابل آليًا بـ `vendor/quran-arabic.json` (نصّ عثماني، رخصته مثبتة في
الملف نفسه) في `tests/lessons-extra.test.js`:

- يُحلَّل المرجع `«القاسم: ٦»` إلى رقم سورة ورقم آية من أسماء المصحف نفسها.
- يُقارَن هيكل الحروف بين الاقتباس الإملائي والرسم العثماني، لأنهما يختلفان
  في المدّية (ٱلصَّلَوٰة في العثماني والصَّلَاة في الإملائي) وفي إظهار الهمزة.
- الفحص **يقبل** المرجع الصحيح، و**يرفض** المرجع الخاطئ ورقم الآية الخاطئ
  والنصّ المختلق — وهو ما اختُبر صراحةً في `الفحص يرفض المرجع الخاطئ والنصّ المختلق`.

> ⚠️ **حدود هذا العمل**: الآيات متحقَّق منها آليًّا، أمّا الأحكام الفقهية وآدابُها
> فهي من تحرير الطالب ولا تحمل تخريجًا، ولذلك تظهر الخمسة في `npm run review`
> تحت «دروس الآداب المضافة — يحتاج مراجعة». ولم يُؤخذ فيها حديثٌ برقمه إلا بذكر
> المجموعة، ولا يُدّعَى أنها منقولة من ملف مرجعي.

### ملاحظة عن التلوّث اللغوي

أُنتجت النسخة الأولى من هذا الملف وفيها شوائب داخل النصّ العربي: كلمة لاتينية
ملتصقة بحرف عربي (`Leave` مسابَقة بكلمة، و`_ARM` داخل جملة، وإRIX وBrigid)،
وعلامتا ترقيم بلا معنى في اسم مصدر. كُشفت بمراجعة بشرية ثم استُبدلت، ثم
صُنع لها اختبار دائم (`لا تلوّث لغوي في نصوص الدروس المضافة`) يرفض أي حرف غير
عربي أو كلمة لاتينية داخل نصّ عربي، ويشمل خطّ الأساس لدروس المصدر.

## المراجعة العلمية

الأداة لا تحكم على صحّة النصّ، ولا تُصلحه. تجيب عن سؤال واحد لكل عنصر:
**هل يحمل هذا النصّ تخريجًا أم يحتاج إلى مراجعة عالم؟**

```sh
npm run review        # تقرير في الطرفية
npm run review:ci     # مع فشل CI عند غياب التخريج في مجموعة تمنع النشر
```

ويوجد مقابلها **ورقة مراجعة في المتصفح**: `src/site/review.html`
(مستبعدة من الفهرسة بـ `noindex`، وبها بحث وتصفية بحسب الحالة وطباعة).
تعتمد الورقة والتقرير على تعريف واحد في `src/lib/review.js`.

قاعدة الأداة: غياب التخريج **يمنع النشر** في النصوص المنقولة حرفيًّا
(الأدعية ١٣ · الأحاديث ١٠ · الأذكار ٨)، ويستدعي الانتباه فقط في المجموعات
الوصفية (السيرة · الأنبياء · الأقوال).

### النتيجة الحالية

| المجموعة | العدد | المخارج | بلا تخريج | الحكم |
|---|---|---|---|---|
| الأدعية | ١٣ | ١٣ | ٠ | ✔ |
| الأحاديث | ١٠ | ١٠ | ٠ | ✔ |
| الأذكار | ٨ | ٠ | **٨** | ⛔ يمنع النشر |
| محاور السيرة | ٦ | ٠ | ٦ | ⚠️ |
| الأنبياء | ٦ | ٠ | ٦ | ⚠️ |
| الأقوال | ١٩ | ١٩ | ٠ | ✔ |

**العناصر الثمانية التي تمنع النشر هي الأذكار**، ونصّها موجود في المصدر بلا
تخريج (`ref` فارغ). وحينما يكون النصّ قرآنيًّا فالذكرُ بسورته يكفي، وأما الأذكار
النبوية فتحتاج رقمًا في السنن مع درجته. `tests/review.test.js` يفرض ألّا
يخلو دعاء أو حديث من تخريجه.

> **ما تحقّق من هذه الأداة فعلًا**: كشف أن دمج `SEERAH` أدخل محورين مكرَّرين
> («الهجرة» مقابل «الهجرة إلى المدينة»، «الوفاة» مقابل «وفاة النبي ﷺ») لأن
> المطابقة كانت على العنوان الحرفي. صُحّح ذلك بـ `seerahMatcher` في
> `scripts/extract/merge-legacy.cjs`، وأُعيدت السيرة إلى ٦ محاور، والاختبار
> `SEERAH has no duplicate event` يمنع عودة التكرار.

### كيف تُضاف بيانات جديدة

1. عدّل الملف المرجعي (أو أضف عنصرًا في `src/data/*.js` مباشرة).

   حوّل التمييز إلى `**نص**`; يتولّى `richText()` ترميزه بأمان.

### دمج ملف قديم ناقص

`legacy_html_20260929_997a67.html` نسخة أقدم من `نور الهدى.html`، لكنه يحتوي
أسئلة اختبار وعُلَماء ومحاور سيرة لم تكن في ملفات المصدر المستخدمة.

```sh
npm run merge:legacy          # معاينة: كم عنصرًا سيُضاف
npm run merge:legacy -- --write   # تطبيق فعلي
```

الأداة **لا تولّد أي نص**، بل تنقل حرفيًا من الملف المصدر، وتضيف **العناصر
الفريدة فقط** بعد مطابقة نصّية تتجاهل التشكيل. وهي تعيد توليد ملفات البيانات
بالكامل من البيانات المدمجة (لا تعديل نصّي داخل الملف)، فتُبقي الصيغة
متوازنة. بعد كل دمج تُشغَّل `npm run verify:content` التي تتحقق من:
اكتمال الأسئلة، عدم التكرار، صحة المخطّط، ومطابقة `QUESTION_BANK_SIZE`.

نتيجة الدمج: **١١٢ → ١٥٤ سؤالًا**، **١٨ → ٢١ عالمًا**، **١٨ → ١٩ قولًا**.
السيرة reports `+2` في الدمج الأول، لكن هذين المحورين تكرار لِما سبق
(راجع «المراجعة العلمية» أعلاه)، فأُعيدت إلى ٦ بعد تصحيح المطابقة.
أسماء الله الـ٩٩ لم تتغيّر: كل الأسماء موجودة سلفًا، والفروق مجرد تشكيل.
تشغيل الأداة مرّة ثانية يُظهر `+0` لكل مجموعة (لا تكرار).

### فحص شامل: ما الناقص من المصدر

```sh
npm run merge:all          # يعرض كل عنصر ناقص، بلا تعديل
npm run merge:all -- --write
```

الأداة تدور على **كل** ثوابت البيانات في الملفات الأربعة، وتقارنها بما في
المشروع بعد تطبيع يتجاهل التشكيل والزخرفة واختلاف علامات الترقيم. وتعرض
أيضًا المجموعات المكتملة أصلًا للتأكّد. النتيجة الأخيرة:

| المجموعة | المشروع | الحالة |
|---|---|---|
| الآيات اليومية | ٥ → **١١** | ✔ تغطية كاملة |
| الأحاديث اليومية | ٤ → **٨** | ✔ تغطية كاملة |
| الإذاعة | ١٧ | ✔ مكتملة |
| الأحاديث | ١٠ | ✔ مكتملة |
| أحداث المناسبات | ٩ | ✔ مكتملة |
| الأدعية | ١٣ | ✔ مكتملة |
| أسماء الله | ٩٩ | ✔ مكتملة |
| الدروس | ٩ + ٥ مضافة | ✔ |
| بنك الأسئلة | **١٥٤** | ✔ أوسع من المصدرين |

`npm run verify:content` يفحص هذه التغطية آليًا، فأي حذف لاحق لأي عنصر
من ملف المصدر **يُفشل الفحص** بدل أن يمرّ صامتًا.

## الأمان

- كل نصّ يأتي من المستخدم (نموذج السؤال، اسم المُسند، نصّ البطاقة) يمرّ بـ
  `escapeHtml()` قبل الحقن، ولا يُستخدم `innerHTML` معه مباشرة.
- حقل الفخ `website` موجود في نموذج السؤال ويُرفض صامتًا إن امتلأ.
- `Permissions-Policy` في `vercel.json`: الموقع والإشعارات والكاميرا مقيدة.
- `user-scalable=no` غير مستخدم — التكبير متاح.

## الخصوصية

كل ما يُحفظ في `localStorage` (ثيم، خط، تقدّم القراءة، نتائج الاختبارات، أذكار)
يبقى في جهازك. الموقع لا يرسل بيانات لخادم؛ أدوات الطرف الثالث:
Google Fonts للخطوط، `api.aladhan.com` لمواقيت الصلاة (تُرسل الإحداثيات فقط)،
و`api.quran.com` و`alquran.cloud` لنصّ المصحف والتفسير والترجمة (الطلب يحمل
**رقم السورة فقط**، لا بيانات شخصية).

> ⚠️ **مجلس المراجعة العلمية**: الموقع قيد إنشاء مجلس مراجعة من طلاب العلم
> المتخصصين على منهج السلف لمراجعة كل درس. حتى الآن المحتوى مكتوب بمساعدة تقنية
> ويحتاج مراجعة نهائية. النص موجود كما هو في قسم «عن الموقع» — يُحدَّث ولا يُحذف.

### توسيع المحتوى — لم يُنفَّذ، ولهذا السبب

المحاولات الأولى لتوليد هذه النصوص آليًا أنتجت **عربية مشوّهة ومبتورة**
(حروف صينية داخل أسماء الأدعية، كلمات إنجليزية داخل النص العربي، أدعية مكرّرة
بلا معنى). رُدَّت جميعها إلى الملفات الأصلية المُتحقَّق منها، وبقيت البيانات
على حالها: ١٣ دعاءً، ١٠ أحاديث، ٨ سيرة، ٦ أنبياء، و٤ في ركن الأطفال
وأما السيرة والأنبياء فبقيت على حالها من المصدر.

**هذه النصوص لا تُولَّد آليًا.** نصوص الدعاء والحديث والسيرة والأنبياء تُنسب إلى أهلها من الصحابة والتابعين، فلا يجوز أن يُكتب نصٌّ منسوب إلى النبي ﷺ أو إلى صحابي أو عالم دون ضبطه ومراجعة من **أهل العلم**. توليدها آليًا يُدخل أخطاءً في الدين، وهي أخطاء لا يظهرها الفحص الآلي.

المطلوب فعليًا: مراجعة من طالب علم، أو نسخ من مصادر موثوقة مع ذكر التخريج
كموجود في الحقول `ref`، ثم إضافتها ملفًا ملفًا.

> عند كل نشر: ارفع `CACHE_VERSION` في `sw.js` ليخرج المستخدم من الكاش القديم،
> وأعد توليد الأيقونات إن تغيّر التصميم.
